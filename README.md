# NPL_2026

Индивидуальная работа: 20 программ на 20 разных языках программирования. Пять тем, на каждую тему по 4 программы.

## Порядок работы

Каждая задача делается в отдельной ветке. Имя ветки: `<номер темы>_task_<номер задачи>_<язык>`, например `1_task_1_ada`. Исходники лежат в папке своей темы: `<папка темы>/task_<номер>_<язык>/`.

## Тема 1. Многопоточность

Папка: `1_threads/`

| № | Задача | Язык | Ветка |
|:-:|---|---|---|
| 1 | Параллельное построение инвертированного индекса документов | Ada | `1_task_1_ada` |
| 2 | Параллельная маркировка компонент связности бинарной матрицы | Erlang | `1_task_2_erlang` |
| 3 | Параллельная поразрядная сортировка целых чисел | Rust | `1_task_3_rust` |
| 4 | Параллельное вычисление корреляционной матрицы | Kotlin | `1_task_4_kotlin` |

1.1 Параллельное построение инвертированного индекса документов (Ada). Программа получает список текстовых файлов и строит инвертированный индекс: для каждого слова сохраняет названия файлов и позиции его вхождений (порядковые номера слов, начиная с 1). Несколько задач Ada (task) параллельно обрабатывают разные файлы и формируют локальные таблицы вида «слово — файл и позиции». Затем задачи передают локальные результаты в общий защищённый объект (protected object), который объединяет списки вхождений одинаковых слов. Слова приводятся к нижнему регистру; разделителями считаются символы, отличные от латинских букв `a-z`. Итоговый индекс выводится в текстовый файл: слова сортируются по алфавиту, для каждого слова файлы перечисляются по имени, а позиции — по возрастанию.

1.2 Параллельная маркировка компонент связности бинарной матрицы (Erlang). Программа получает из текстового файла прямоугольную матрицу из `0` и `1`; единицы обозначают занятые клетки. Связность — по четырём соседям (вверх, вниз, влево, вправо), диагональное касание не считается соединением. Матрица разбивается на непересекающиеся полосы строк. Для каждой полосы создаётся отдельный процесс Erlang, который локально помечает компоненты и посылает координатору результаты сообщением.

1.3 Параллельная поразрядная сортировка целых чисел (Rust). Реализовать устойчивую сортировку 32-битных знаковых целых чисел методом LSD radix sort по четырём байтам от младшего к старшему. Для корректного порядка отрицательных чисел при обработке старшего разряда учесть знаковый бит (например, сортировать ключ `x XOR 0x80000000`).

1.4 Параллельное вычисление корреляционной матрицы (Kotlin). Входная таблица CSV содержит числовые наблюдения: строки — объекты, столбцы — признаки, первая строка — заголовки. Требуется построить симметричную матрицу коэффициентов корреляции Пирсона между всеми парами столбцов. Для каждого признака сначала вычисляются среднее и сумма квадратов отклонений; затем пары `(i, j)` верхнего треугольника распределяются между задачами пула потоков (`ExecutorService`).

## Тема 2. Алгоритмические задачи

Папка: `2_algorithms/`

| № | Задача | Язык | Ветка |
|:-:|---|---|---|
| 1 | Рекурсивная генерация двоичного кода Грея | Haskell | `2_task_1_haskell` |
| 2 | Поиск компонент сильной связности ориентированного графа | Prolog | `2_task_2_prolog` |
| 3 | Построение выпуклой оболочки точек методом QuickHull | OCaml | `2_task_3_ocaml` |
| 4 | Поиск максимального потока рекурсивным поиском дополняющих путей | Clojure | `2_task_4_clojure` |

2.1 Рекурсивная генерация двоичного кода Грея (Haskell). По введённому целому `n >= 0` сгенерировать все двоичные строки длины `n` в отражённом порядке Грея. Основная функция реализуется рекурсивно по формуле: для `n = 0` список содержит пустую строку; для `n > 0` к предыдущему списку слева добавляется `0`, а к его перевёрнутой копии — `1`. Порядок строк фиксирован, одинаковые комбинации не допускаются.

2.2 Поиск компонент сильной связности ориентированного графа (Prolog). Граф задаётся числом вершин и списком ориентированных рёбер. Реализовать алгоритм Косарайю: рекурсивный обход в глубину исходного графа формирует порядок завершения вершин, после транспонирования графа рекурсивные обходы в обратном порядке выделяют компоненты сильной связности. Состояние посещённых вершин передавать явно через аргументы предикатов, без неограниченного создания динамических фактов.

2.3 Построение выпуклой оболочки точек методом QuickHull (OCaml). На плоскости задано множество целочисленных точек `(x, y)`. Построить выпуклую оболочку методом QuickHull: найти крайние точки по оси X, разделить остальные точки по сторонам прямой, затем рекурсивно выбирать наиболее удалённую точку и делить задачу на две меньшие области. При равенстве расстояний использовать устойчивое правило выбора (лексикографический порядок).

2.4 Поиск максимального потока рекурсивным поиском дополняющих путей (Clojure). Ориентированная сеть задаётся вершинами, рёбрами с неотрицательными целочисленными пропускными способностями, истоком `s` и стоком `t` (`s != t`). Реализовать алгоритм Форда—Фалкерсона с рекурсивным DFS в остаточной сети: поиск дополняющего пути должен учитывать как прямые, так и обратные остаточные рёбра; после каждого пути обновлять остаточные ёмкости. Нельзя допускать повторного посещения вершины в пределах одного поиска.

## Тема 3. Ввод/вывод в консоль и файл

Папка: `3_io/`

| № | Задача | Язык | Ветка |
|:-:|---|---|---|
| 1 | Удаление дубликатов CSV-записей по ключу | Perl | `3_task_1_perl` |
| 2 | Сравнение снимков каталогов по манифестам | Lua | `3_task_2_lua` |
| 3 | Создание и применение бинарного патча | Nim | `3_task_3_nim` |
| 4 | Построение индекса байтовых смещений строк большого файла | Zig | `3_task_4_zig` |

3.1 Удаление дубликатов CSV-записей по ключу (Perl). Прочитать CSV-файл с заголовком, указанным символом-разделителем (по умолчанию запятая) и полями, которые могут содержать запятые, кавычки и перевод строки внутри кавычек. Пользователь задаёт имя столбца-ключа; строки с повторяющимся значением этого поля считаются дубликатами. Сохранять первую запись каждого ключа и исходный порядок оставшихся записей. Значения ключей сравнивать без автоматического изменения регистра или пробелов.

3.2 Сравнение снимков каталогов по манифестам (Lua). Программа сравнивает два заранее созданных снимка каталога в виде текстовых манифестов. Каждая строка манифеста имеет формат `relative_path<TAB>size<TAB>sha256`, где путь относительный, размер — число байт, а хеш SHA-256 записан 64 шестнадцатеричными символами. Не требуется обходить файловую систему или самостоятельно вычислять SHA-256: анализируются именно переданные файлы-манифесты.

3.3 Создание и применение бинарного патча (Nim). Реализовать две консольные команды: `create old.bin new.bin patch.bin` и `apply old.bin patch.bin restored.bin`. Формат патча разработать и документировать: сигнатура формата, версия, исходный и целевой размеры, контрольная сумма исходного файла и последовательность операций `COPY(offset, length)` / `INSERT(length, bytes)`.

3.4 Построение индекса байтовых смещений строк большого файла (Zig). Разработать утилиту, которая обрабатывает текстовый файл потоково, не загружая его целиком в память, и строит бинарный индекс начальных байтовых смещений каждой строки. Разделитель строк — байт LF (`0x0A`); для файлов с CRLF символ CR считается частью данных, но не образует отдельную строку. Первая строка начинается со смещения 0. Не создавать фиктивную пустую строку после завершающего LF.

## Тема 4. Клиент-серверное взаимодействие

Папка: `4_client_server/`

| № | Задача | Язык | Ветка |
|:-:|---|---|---|
| 1 | TCP-сервер агрегации телеметрии | Elixir | `4_task_1_elixir` |
| 2 | HTTP-сервер коротких ссылок | Ruby | `4_task_2_ruby` |
| 3 | TCP-сервер запросов маршрутов по взвешенному графу | D | `4_task_3_d` |
| 4 | Сетевая игра в цепочку слов | Julia | `4_task_4_julia` |

4.1 TCP-сервер агрегации телеметрии (Elixir). Сервер принимает одновременные TCP-подключения от нескольких датчиков через `:gen_tcp`. Каждое сообщение — отдельная строка `sensor_id;timestamp;value`, где `sensor_id` не содержит `;`, `timestamp` — целое время Unix в секундах, `value` — конечное вещественное число.

4.2 HTTP-сервер коротких ссылок (Ruby). Реализовать небольшой HTTP-сервис на `TCPServer` (без веб-фреймворка) для создания и перенаправления коротких ссылок. Запрос `POST /links` с телом `url=https://...` создаёт уникальный короткий код и возвращает `201 Created` с JSON-полями `code` и `short_path`. Запрос `GET /<code>` возвращает `302 Found` с заголовком `Location` для исходного URL; `GET /stats/<code>` возвращает число переходов, увеличиваемое только при успешном перенаправлении.

4.3 TCP-сервер запросов маршрутов по взвешенному графу (D). Сервер при запуске загружает из файла ориентированный граф с неотрицательными целочисленными весами. По TCP принимает строковые запросы `PATH start finish` от нескольких клиентов и возвращает кратчайший путь, рассчитанный алгоритмом Дейкстры. Если существует несколько путей с одинаковой минимальной длиной, использовать детерминированное правило выбора (например, лексикографически минимальную последовательность вершин).

4.4 Сетевая игра в цепочку слов (Julia). TCP-сервер обслуживает одну игровую комнату для 2–4 игроков. Клиенты соединяются по сети, выбирают уникальные имена и по очереди отправляют команды `WORD word`. Очередное слово должно начинаться с последней буквы предыдущего, не повторять уже произнесённые слова и содержать только латинские буквы `a-z` (без внешнего словаря: любое такое слово считается допустимым). Сравнение регистронезависимое.

## Тема 5. Конвертация данных из одного формата в другой

Папка: `5_convert/`

| № | Задача | Язык | Ветка |
|:-:|---|---|---|
| 1 | GeoJSON в CSV | F# | `5_task_1_fsharp` |
| 2 | SQL DDL в Graphviz DOT | Scala | `5_task_2_scala` |
| 3 | LDIF в CSV | Groovy | `5_task_3_groovy` |
| 4 | PPM (P6) в BMP (24-bit) | Swift | `5_task_4_swift` |

5.1 GeoJSON в CSV (F#). Преобразовать коллекцию GeoJSON `FeatureCollection` в CSV-таблицу точечных объектов. Поддерживаются только геометрии `Point` с координатами `[longitude, latitude]` и значениями свойств-примитивов (строка, число, логическое значение, `null`), вложенные структуры свойств отклоняются с указанием ошибки. В CSV должны присутствовать столбцы `longitude`, `latitude` и объединённый набор имён свойств, отсортированный по имени; у объектов с отсутствующим свойством поле остаётся пустым.

5.2 SQL DDL в Graphviz DOT (Scala). Прочитать SQL-файл со схемой базы данных и создать ориентированный граф связей таблиц в синтаксисе Graphviz DOT. Поддерживаемое подмножество SQL: `CREATE TABLE name (...)`, обычные объявления столбцов, `PRIMARY KEY` и `FOREIGN KEY (col) REFERENCES other_table (col)`; ключевые слова нечувствительны к регистру, идентификаторы состоят из букв, цифр и подчёркиваний.

5.3 LDIF в CSV (Groovy). Конвертировать записи каталога в формате LDIF (упрощённое подмножество RFC 2849) в табличный CSV. Записи разделяются пустой строкой, атрибуты имеют вид `name: value`, первая строка продолжения с начальным пробелом присоединяется к предыдущему значению без этого пробела. Повторяющиеся атрибуты одного объекта объединяются через `;` в одной ячейке, но каждое значение предварительно экранируется по оговорённому правилу; имена атрибутов в заголовке сортируются, `dn` помещается первым.

5.4 PPM (P6) в BMP (24-bit) (Swift). Преобразовать двоичное RGB-изображение PPM с магическим числом `P6` в несжатый BMP формата 24 бита на пиксель. В заголовке PPM обработать произвольные ASCII-пробелы и комментарии `#` до конца строки; поддерживать только `maxval = 255` и положительные ширину/высоту. После отделяющего пробельного символа читать ровно `width * height * 3` байт RGB, не интерпретируя их как текст.
