# NPL_2026

Индивидуальная работа по новым языкам программирования: **20 программ на 20 разных языках**, объединённых в **5 тем по 4 задания**. Каждое задание реализуется самостоятельно на закреплённом языке. Формулировка задания **1.1 на Ada** оставлена без изменения, а его исходный код в репозитории не затрагивается; задания **1.2–5.4** сформулированы заново.

## Порядок работы

Каждая задача делается в отдельной ветке. Имя ветки: `<номер темы>_task_<номер задачи>_<язык>`, например `1_task_1_ada`. Исходники лежат в папке своей темы: `<папка темы>/task_<номер>_<язык>/`.

Для каждой программы необходимо предусмотреть корректный пример входных данных, ожидаемый результат и проверку ошибочного или граничного ввода. Для многопоточных задач дополнительно сравниваются параллельное и последовательное вычисления; для клиент-серверных — проверяется взаимодействие минимум двух клиентов; для конвертеров — сохраняются исходные данные в пределах заявленного поддерживаемого подмножества формата. В алгоритмической теме **все четыре решения предусматривают рекурсивные процедуры/функции**.

### 1.1. Производитель-потребитель на задачах и защищённом объекте (Ada)

Два производителя кладут числа в общий кольцевой буфер на 5 элементов, два потребителя забирают их оттуда. Буфер сделан защищённым объектом (protected) с барьерами на вход, поэтому при заполненном или пустом буфере задачи ждут сами, без ручных блокировок. В конце каждый потребитель печатает сумму полученных чисел.

### 1.2. Параллельная маркировка компонент связности бинарной матрицы (Erlang)

Программа получает из текстового файла прямоугольную матрицу из `0` и `1`; единицы обозначают занятые клетки. Связность — **по четырём соседям** (вверх, вниз, влево, вправо), диагональное касание не считается соединением. Матрица разбивается на непересекающиеся полосы строк. Для каждой полосы создаётся отдельный процесс Erlang, который локально помечает компоненты и посылает координатору результаты сообщением. Координатор объединяет метки, соприкасающиеся на границах полос, и перенумеровывает итоговые компоненты начиная с 1 в порядке первого появления при построчном обходе.

**Ввод:** файл с размерами `rows cols` и `rows` строками по `cols` значений `0`/`1`; число рабочих процессов задаётся аргументом. **Вывод:** число компонент и матрица меток, где `0` соответствует свободной клетке. Предусмотреть пустую по единицам матрицу, единственную компоненту, узкие полосы и случай, когда число процессов больше количества строк. Результат должен совпадать с последовательной проверочной реализацией вне зависимости от числа процессов.

### 1.3. Параллельная поразрядная сортировка целых чисел (Rust)

Реализовать устойчивую сортировку **32-битных знаковых целых чисел** методом LSD radix sort по четырём байтам от младшего к старшему. Для корректного порядка отрицательных чисел при обработке старшего разряда учесть знаковый бит (например, сортировать ключ `x XOR 0x80000000`). На каждом проходе несколько потоков (`std::thread`) строят локальные гистограммы для 256 значений байта; главный поток вычисляет глобальные префиксные суммы и диапазоны записи каждого потока, после чего выполняется параллельная устойчивая раскладка в отдельный выходной буфер. Записи потоков не должны перекрываться; гонки данных и общий `Mutex` на каждый элемент не допускаются.

**Ввод:** список чисел из текстового файла и число потоков. **Вывод:** отсортированный список и время сортировки. Проверить массивы с повторами, отрицательными числами, границами `i32`, пустым вводом и один элемент. Сравнить с `sort()` из стандартной библиотеки для 1, 2 и 4 потоков; измерение времени не является проверкой корректности.

### 1.4. Параллельное вычисление корреляционной матрицы (Kotlin)

Входная таблица CSV содержит числовые наблюдения: строки — объекты, столбцы — признаки, первая строка — заголовки. Требуется построить симметричную матрицу коэффициентов корреляции Пирсона между всеми парами столбцов. Для каждого признака сначала вычисляются среднее и сумма квадратов отклонений; затем пары `(i, j)` верхнего треугольника распределяются между задачами пула потоков (`ExecutorService`). Вычисление отдельной пары независимо, нижний треугольник заполняется отражением результата. Для столбца с нулевой дисперсией выводить `NA`, включая его диагональ; для остальных диагональ равна 1.

**Ввод:** путь к CSV и количество потоков. **Вывод:** CSV корреляционной матрицы с названиями признаков и коэффициентами с фиксированной точностью. Проверить идеально положительную/отрицательную корреляцию, константный столбец, неполные строки и недостаточное число наблюдений. Для допустимого ввода разность с последовательной реализацией должна быть не более `1e-9`.

### 2.1. Рекурсивная генерация двоичного кода Грея (Haskell)

По введённому целому `n >= 0` сгенерировать все двоичные строки длины `n` в отражённом порядке Грея. Основная функция реализуется **рекурсивно** по формуле: для `n = 0` список содержит пустую строку; для `n > 0` к предыдущему списку слева добавляется `0`, а к его перевёрнутой копии — `1`. Порядок строк фиксирован, одинаковые комбинации не допускаются.

**Ввод:** число `n` (ограничить разумным пределом, например `0..16`, так как результат имеет размер `2^n`). **Вывод:** по одной кодовой комбинации в строке, дополнительно количество комбинаций. Проверить, что все строки уникальны, их ровно `2^n` и любые две соседние, включая последнюю и первую, различаются одним битом. Для `n=0` корректно обработать единственную пустую комбинацию.

### 2.2. Поиск компонент сильной связности ориентированного графа (Prolog)

Граф задаётся числом вершин и списком ориентированных рёбер. Реализовать алгоритм Косарайю: **рекурсивный обход в глубину** исходного графа формирует порядок завершения вершин, после транспонирования графа рекурсивные обходы в обратном порядке выделяют компоненты сильной связности. Состояние посещённых вершин передавать явно через аргументы предикатов, без неограниченного создания динамических фактов. В итоговом отчёте отсортировать номера вершин внутри каждой компоненты, а сами компоненты — по наименьшей вершине, чтобы результат был однозначным.

**Ввод:** текстовый файл: в первой строке `V E`, затем `E` пар вершин с номерами от `1` до `V`. **Вывод:** число компонент и перечень их вершин. Проверить циклический граф, ориентированную цепочку, изолированные вершины, петли и повторяющиеся рёбра; некорректные номера вершин отклонять.

### 2.3. Построение выпуклой оболочки точек методом QuickHull (OCaml)

На плоскости задано множество целочисленных точек `(x, y)`. Построить выпуклую оболочку методом QuickHull: найти крайние точки по оси X, разделить остальные точки по сторонам прямой, затем **рекурсивно** выбирать наиболее удалённую точку и делить задачу на две меньшие области. При равенстве расстояний использовать устойчивое правило выбора (лексикографический порядок). Внутренние точки и промежуточные коллинеарные точки в вершины оболочки не включать.

**Ввод:** файл с количеством точек и их координатами. **Вывод:** вершины оболочки против часовой стрелки, начиная с лексикографически минимальной точки; для 0, 1 или 2 уникальных точек вернуть имеющиеся точки. Обработать дубликаты и случай, когда все точки лежат на одной прямой (выводятся только две крайние). Проверить, что все входные точки расположены внутри или на границе полученного выпуклого многоугольника.

### 2.4. Поиск максимального потока рекурсивным поиском дополняющих путей (Clojure)

Ориентированная сеть задаётся вершинами, рёбрами с **неотрицательными целочисленными пропускными способностями**, истоком `s` и стоком `t` (`s != t`). Реализовать алгоритм Форда—Фалкерсона с **рекурсивным DFS** в остаточной сети: поиск дополняющего пути должен учитывать как прямые, так и обратные остаточные рёбра; после каждого пути обновлять остаточные ёмкости. Нельзя допускать повторного посещения вершины в пределах одного поиска. Для завершения при целых ёмкостях каждое увеличение потока выполняется на минимум остаточных ёмкостей пути.

**Ввод:** `V E s t` и `E` строк формата `u v capacity`. **Вывод:** максимальный поток, величины потоков по исходным рёбрам и множество вершин, достижимых из истока в итоговой остаточной сети (для проверки минимального разреза). Обработать отсутствие пути, параллельные рёбра и нулевые ёмкости; проверить равенство значения потока ёмкости найденного минимального разреза.

### 3.1. Удаление дубликатов CSV-записей по ключу (Perl)

Прочитать CSV-файл с заголовком, указанным символом-разделителем (по умолчанию запятая) и полями, которые могут содержать запятые, кавычки и перевод строки внутри кавычек. Пользователь задаёт имя столбца-ключа; строки с повторяющимся значением этого поля считаются дубликатами. Сохранять **первую** запись каждого ключа и исходный порядок оставшихся записей. Значения ключей сравнивать без автоматического изменения регистра или пробелов. Реализовать CSV-разбор и корректную запись с экранированием (возможно использование стандартного для среды модуля `Text::CSV_XS`, если это указано в инструкции по установке).

**Ввод:** имя входного и выходного CSV-файлов, столбец-ключ и необязательный разделитель. **Вывод:** новый CSV и отчёт в консоли: считано, оставлено, удалено. ### 3.2. Сравнение снимков каталогов по манифестам (Lua)

Программа сравнивает два заранее созданных снимка каталога в виде текстовых манифестов. Каждая строка манифеста имеет формат `relative_path<TAB>size<TAB>sha256`, где путь относительный, размер — число байт, а хеш SHA-256 записан 64 шестнадцатеричными символами. Не требуется обходить файловую систему или самостоятельно вычислять SHA-256: анализируются именно переданные файлы-манифесты. По ключу `relative_path` определить добавленные, удалённые и изменённые файлы (изменение размера либо хеша); совпадающие записи в отчёт не включать.

**Ввод:** пути к двум манифестам. **Вывод:** отсортированный по пути отчёт с пометками `ADDED`, `REMOVED`, `CHANGED` и суммарные количества каждой категории; отчёт записывается в файл и печатается в консоль. Пустой манифест допускается. Повторяющийся путь, отрицательный размер или некорректный хеш должны приводить к понятной ошибке. Разделителем является именно TAB, пути могут содержать пробелы.

### 3.3. Создание и применение бинарного патча (Nim)

Реализовать две консольные команды: `create old.bin new.bin patch.bin` и `apply old.bin patch.bin restored.bin`. Формат патча разработать и документировать: сигнатура формата, версия, исходный и целевой размеры, контрольная сумма исходного файла и последовательность операций `COPY(offset, length)` / `INSERT(length, bytes)`. При построении патча допустим простой алгоритм сравнения блоков фиксированного размера с поиском совпадений в старом файле; цель — корректное восстановление, а не оптимальное сжатие. Все числовые поля записывать в едином порядке байтов и проверять границы чтения.

**Вывод:** двоичный файл патча и, при применении, восстановленный файл. Для проверки требовать побайтовое совпадение восстановленного файла с `new.bin`; патч с неправильной сигнатурой, повреждёнными данными, неверной суммой исходного файла или ссылкой за пределы исходного файла отклонять. Проверить одинаковые файлы, пустые файлы, вставки и удаления в начале/середине/конце.

### 3.4. Построение индекса байтовых смещений строк большого файла (Zig)

Разработать утилиту, которая обрабатывает текстовый файл **потоково**, не загружая его целиком в память, и строит бинарный индекс начальных байтовых смещений каждой строки. Разделитель строк — байт LF (`0x0A`); для файлов с CRLF символ CR считается частью данных, но не образует отдельную строку. Первая строка начинается со смещения 0. Не создавать фиктивную пустую строку после завершающего LF. Затем по номеру строки (нумерация с 1) утилита должна через `seek` и индекс прочитать только нужную строку.

**Команды:** `index input.txt input.idx` и `get input.txt input.idx line_number`. **Вывод:** сообщение о количестве строк и байтовый текст искомой строки. В индексе хранить сигнатуру, версию, размер исходного файла и 64-битные смещения; при несовпадении размера исходного файла индекс считать устаревшим. Проверить пустой файл, отсутствие LF в конце, CRLF, длинную строку и запрос за границами.

### 4.1. TCP-сервер агрегации телеметрии (Elixir)

Сервер принимает одновременные TCP-подключения от нескольких датчиков через `:gen_tcp`. Каждое сообщение — отдельная строка `sensor_id;timestamp;value`, где `sensor_id` не содержит `;`, `timestamp` — целое время Unix в секундах, `value` — конечное вещественное число. Для каждого датчика хранить количество измерений, минимум, максимум и среднее значение; обновление агрегатов должно выполняться через один процесс состояния (`GenServer`) либо эквивалентный механизм, исключающий гонки. Команда `STATS sensor_id` возвращает агрегаты, `STATS ALL` — агрегаты для всех датчиков по имени, `QUIT` закрывает соединение.

**Вывод:** ответы `OK`, `ERR ...` и данные агрегатов в заранее описанном текстовом формате. Проверить два одновременно работающих клиента, новый датчик, несуществующий датчик, некорректное число, оборванное соединение и корректность статистики после всех сообщений. Данные хранятся в памяти до завершения сервера.

### 4.2. HTTP-сервер коротких ссылок (Ruby)

Реализовать небольшой HTTP-сервис на `TCPServer` (без веб-фреймворка) для создания и перенаправления коротких ссылок. Запрос `POST /links` с телом `url=https://...` создаёт уникальный короткий код и возвращает `201 Created` с JSON-полями `code` и `short_path`. Запрос `GET /<code>` возвращает `302 Found` с заголовком `Location` для исходного URL; `GET /stats/<code>` возвращает число переходов, увеличиваемое только при успешном перенаправлении. Данные можно хранить в памяти; код не должен изменяться при повторном обращении.

**Клиент:** отдельный консольный скрипт, выполняющий создание ссылки, переход и запрос статистики. Учесть ограничения на длину запроса и URL, корректно читать `Content-Length`, отличать неизвестный код (`404`) от ошибочного URL (`400`), экранировать JSON-строки. Поддерживать несколько последовательных клиентов и минимум два одновременно открытых соединения без порчи состояния.

### 4.3. TCP-сервер запросов маршрутов по взвешенному графу (D)

Сервер при запуске загружает из файла ориентированный граф с неотрицательными целочисленными весами. По TCP принимает строковые запросы `PATH start finish` от нескольких клиентов и возвращает кратчайший путь, рассчитанный алгоритмом Дейкстры. Если существует несколько путей с одинаковой минимальной длиной, использовать детерминированное правило выбора (например, лексикографически минимальную последовательность вершин). Граф после загрузки только читается, поэтому запросы могут обрабатываться параллельно; для каждого клиента использовать отдельный обработчик.

**Ввод графа:** `V E` и пары вершин с весом `u v w`. **Ответ:** `OK distance: v1 v2 ...` либо `NO_PATH`/`ERR message`. Реализовать консольный TCP-клиент. Проверить два независимых одновременных запроса, маршрут из вершины в неё же, недостижимую вершину, неверный синтаксис, отрицательный вес в файле (ошибка при запуске) и корректное завершение соединения по `QUIT`.

### 4.4. Сетевая игра в цепочку слов (Julia)

TCP-сервер обслуживает одну игровую комнату для 2–4 игроков. Клиенты соединяются по сети, выбирают уникальные имена и по очереди отправляют команды `WORD word`. Очередное слово должно начинаться с последней буквы предыдущего, не повторять уже произнесённые слова и содержать только латинские буквы `a-z` (без внешнего словаря: любое такое слово считается допустимым). Сравнение регистронезависимое. После удачного хода сервер сообщает всем текущее слово и следующего игрока. Неправильный ход отвергается и не передаёт очередь. Команда `PASS` пропускает ход, `QUIT` выводит участника из игры; при одном оставшемся игроке сервер объявляет победителя.

**Протокол:** строки UTF-8 с `\n`; сообщения сервера имеют префиксы `OK`, `ERR`, `TURN`, `WIN`. Написать отдельного консольного клиента, который принимает сообщения сервера независимо от ввода пользователя. Проверить два клиента, повтор слова, неправильную первую букву, пропуск хода и отключение во время своего хода. Общее игровое состояние изменяется в одном синхронизированном обработчике (например, через `Channel` и задачи `@async`).

### 5.1. GeoJSON в CSV (F#)

Преобразовать коллекцию GeoJSON `FeatureCollection` в CSV-таблицу точечных объектов. Поддерживаются только геометрии `Point` с координатами `[longitude, latitude]` и значениями свойств-примитивов (строка, число, логическое значение, `null`), вложенные структуры свойств отклоняются с указанием ошибки. В CSV должны присутствовать столбцы `longitude`, `latitude` и объединённый набор имён свойств, отсортированный по имени; у объектов с отсутствующим свойством поле остаётся пустым. Для `null` также записывать пустое поле, явно описав это ограничение преобразования.

**Ввод:** GeoJSON-файл в кодировке UTF-8. **Вывод:** CSV UTF-8 с заголовком, стандартным экранированием кавычек, запятых и переводов строк. Не использовать текстовый поиск скобок вместо JSON-парсинга; разрешён `System.Text.Json`. Проверить несколько точек с разными свойствами, пустую коллекцию, отрицательные координаты, кавычки в строковых полях и неподдерживаемую геометрию.

### 5.2. SQL DDL в Graphviz DOT (Scala)

Прочитать SQL-файл со схемой базы данных и создать ориентированный граф связей таблиц в синтаксисе Graphviz DOT. Поддерживаемое подмножество SQL: `CREATE TABLE name (...)`, обычные объявления столбцов, `PRIMARY KEY` и `FOREIGN KEY (col) REFERENCES other_table (col)`; ключевые слова нечувствительны к регистру, идентификаторы состоят из букв, цифр и подчёркиваний. Для каждой таблицы создать вершину с названием, для каждой внешней связи — ориентированное ребро **от ссылающейся таблицы к целевой**, с меткой `column -> referenced_column`. Несколько внешних ключей между таблицами должны создавать отдельные рёбра.

**Ввод:** `.sql`, содержащий несколько команд, разделённых `;`. **Вывод:** `.dot`, который открывается Graphviz; названия таблиц и подписи экранируются. Игнорировать пустые строки и комментарии `-- ...`, выдавать ошибку для неподдерживаемой конструкции вместо тихой потери данных. Проверить отсутствие внешних ключей, взаимные ссылки, несколько ссылок на одну таблицу и ссылку на несуществующую таблицу.

### 5.3. LDIF в CSV (Groovy)

Конвертировать записи каталога в формате LDIF (упрощённое подмножество RFC 2849) в табличный CSV. Записи разделяются пустой строкой, атрибуты имеют вид `name: value`, первая строка продолжения с начальным пробелом присоединяется к предыдущему значению без этого пробела. Повторяющиеся атрибуты одного объекта объединяются через `;` в одной ячейке, но каждое значение предварительно экранируется по оговорённому правилу; имена атрибутов в заголовке сортируются, `dn` помещается первым. При поддержке строк `name:: base64` декодировать их как UTF-8; недопустимый base64 отклонять.

**Ввод:** LDIF UTF-8. **Вывод:** CSV UTF-8 с одной строкой на запись и корректным экранированием CSV. Проверить разные наборы атрибутов, пустые значения, перенос длинного значения, повторяющийся атрибут и запятые/кавычки в тексте. Если вход содержит директиву изменения (`changetype:`), вернуть понятную ошибку: такие записи не входят в поддерживаемое подмножество.

### 5.4. PPM (P6) в BMP (24-bit) (Swift)

Преобразовать двоичное RGB-изображение PPM с магическим числом `P6` в несжатый BMP формата 24 бита на пиксель. В заголовке PPM обработать произвольные ASCII-пробелы и комментарии `#` до конца строки; поддерживать только `maxval = 255` и положительные ширину/высоту. После отделяющего пробельного символа читать **ровно** `width * height * 3` байт RGB, не интерпретируя их как текст. В BMP сформировать 14-байтный файловый заголовок и 40-байтный заголовок DIB, записать пиксели в порядке BGR снизу вверх, дополнить каждую строку нулями до кратности 4 байтам.

**Ввод:** исходный `.ppm` и имя выходного `.bmp`. **Вывод:** корректный `.bmp` с одинаковыми размерами и цветами. Проверить изображения 1×1, 2×2, ширину с паддингом, комментарии в заголовке, усечённые пиксельные данные и недопустимое значение `maxval`. До выделения памяти проверять переполнение при вычислении размеров и корректность длины файла.
