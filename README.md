# NPL_2026

Индивидуальная работа: 20 программ на 20 разных языках программирования. Пять тем, на каждую тему по 4 программы.

## Порядок работы

Каждая задача делается в отдельной ветке. Имя ветки: `<номер темы>_task_<номер задачи>_<язык>`, например `1_task_1_ada`. Исходники лежат в папке своей темы: `<папка темы>/task_<номер>_<язык>/`.

## Тема 1. Многопоточность

Папка: `1_threads/`

| № | Задача | Язык | Ветка |
|:-:|:-:|:-:|:-:|
| 1 | Производитель-потребитель на задачах и защищённом объекте | Ada | `1_task_1_ada` |
| 2 | Параллельное суммирование массива процессами | Erlang | `1_task_2_erlang` |
| 3 | Параллельный подсчёт простых чисел в диапазоне | Rust | `1_task_3_rust` |
| 4 | Обедающие философы на потоках | Kotlin | `1_task_4_kotlin` |

1.1 Производитель-потребитель на задачах и защищённом объекте (Ada). Два производителя кладут числа в общий кольцевой буфер на 5 элементов, два потребителя забирают их оттуда. Буфер сделан защищённым объектом (protected) с барьерами на вход, поэтому при заполненном или пустом буфере задачи ждут сами, без ручных блокировок. В конце каждый потребитель печатает сумму полученных чисел.

1.2 Параллельное суммирование массива процессами (Erlang). Массив делится на равные части, для каждой части запускается отдельный процесс. Процессы считают частичные суммы и отправляют их родительскому процессу сообщениями. Родитель собирает ответы, складывает их и сравнивает с результатом последовательного суммирования.

1.3 Параллельный подсчёт простых чисел в диапазоне (Rust). Диапазон делится между несколькими потоками std::thread. Каждый поток считает простые числа в своей части и передаёт результат главному потоку через канал mpsc. Общий счётчик защищён связкой Arc и Mutex. В конце печатаются итоговое количество простых чисел и время работы для разного числа потоков.

1.4 Обедающие философы на потоках (Kotlin). Пять философов по очереди размышляют и едят, для еды нужны две вилки, каждая вилка защищена блокировкой из java.util.concurrent. Вилки берутся в фиксированном порядке, чтобы не возникала взаимная блокировка. По таймеру печатается, сколько раз поел каждый философ.

## Тема 2. Алгоритмические задачи

Папка: `2_algorithms/`

| № | Задача | Язык | Ветка |
|:-:|:-:|:-:|:-:|
| 1 | Задача о N ферзях (рекурсия) | Haskell | `2_task_1_haskell` |
| 2 | Ханойские башни (рекурсия) | Prolog | `2_task_2_prolog` |
| 3 | Быстрая сортировка и обход бинарного дерева поиска (рекурсия) | OCaml | `2_task_3_ocaml` |
| 4 | Кратчайший путь в лабиринте поиском в ширину | Clojure | `2_task_4_clojure` |

2.1 Задача о N ферзях (Haskell). Размер доски читается с консоли. Рекурсивная функция ставит ферзя в очередную строку, проверяет столбец и обе диагонали и идёт дальше, при неудаче откатывается. Печатаются число решений и первая найденная расстановка.

2.2 Ханойские башни (Prolog). Правило перемещения n дисков между тремя стержнями записано рекурсивно. Программа печатает последовательность ходов и считает их число, которое сверяется с формулой 2^n − 1.

2.3 Быстрая сортировка и обход бинарного дерева поиска (OCaml). Быстрая сортировка списка написана рекурсивно с разбиением относительно опорного элемента. Из тех же чисел строится бинарное дерево поиска, затем выполняются рекурсивные обходы: прямой, симметричный и обратный. Отсортированный список сравнивается с результатом симметричного обхода.

2.4 Кратчайший путь в лабиринте поиском в ширину (Clojure). Лабиринт читается из текстового файла, где стены, старт и финиш заданы символами. Поиск в ширину использует очередь и множество посещённых клеток. Выводится длина пути и лабиринт с отмеченным маршрутом, а если пути нет, об этом сообщается.

## Тема 3. Ввод/вывод в консоль и файл

Папка: `3_io/`

| № | Задача | Язык | Ветка |
|:-:|:-:|:-:|:-:|
| 1 | Частотный анализ слов в текстовом файле | Perl | `3_task_1_perl` |
| 2 | Консольная записная книжка с хранением в файле | Lua | `3_task_2_lua` |
| 3 | Построчная обработка лог-файла и отчёт | Nim | `3_task_3_nim` |
| 4 | Статистика по числам из консоли или файла | Zig | `3_task_4_zig` |

3.1 Частотный анализ слов в текстовом файле (Perl). Файл читается построчно, текст приводится к нижнему регистру и разбивается на слова. Частоты считаются в хеше, затем печатаются слова по убыванию частоты. Результат выводится на экран и записывается в отдельный файл.

3.2 Консольная записная книжка с хранением в файле (Lua). В цикле читаются команды: add, list, del, find, exit. Записи хранятся в текстовом файле, при запуске он читается, после каждого изменения перезаписывается. Неверный ввод проверяется и не ломает программу.

3.3 Построчная обработка лог-файла и отчёт (Nim). Лог читается построчно, из строк выделяются время, уровень (INFO, WARN, ERROR) и сообщение. С консоли запрашивается уровень для фильтра. Подходящие записи выводятся, а итоговый отчёт с количеством записей по каждому уровню сохраняется в файл.

3.4 Статистика по числам из консоли или файла (Zig). Числа читаются из стандартного ввода или из файла, путь к которому передан аргументом. Вычисляются минимум, максимум, сумма и среднее значение. Результат печатается на экран и записывается в выходной файл.

## Тема 4. Клиент-серверное взаимодействие

Папка: `4_client_server/`

| № | Задача | Язык | Ветка |
|:-:|:-:|:-:|:-:|
| 1 | Эхо-чат по TCP на несколько клиентов | Elixir | `4_task_1_elixir` |
| 2 | HTTP-сервер и HTTP-клиент на сокетах | Ruby | `4_task_2_ruby` |
| 3 | TCP-сервер с командами SET и GET | D | `4_task_3_d` |
| 4 | Сервер вычислений арифметических выражений | Julia | `4_task_4_julia` |

4.1 Эхо-чат по TCP на несколько клиентов (Elixir). Сервер на gen_tcp принимает подключения, для каждого клиента запускается отдельный процесс. Сообщение одного клиента рассылается всем остальным. Поддерживаются ник при входе и команда выхода.

4.2 HTTP-сервер и HTTP-клиент на сокетах (Ruby). Сервер на TCPServer сам разбирает строку запроса и заголовки, отвечает на GET для нескольких путей и возвращает 404 на неизвестный путь. Клиент отправляет запрос по сокету и печатает статус и тело ответа. Готовые веб-фреймворки не используются.

4.3 TCP-сервер с командами SET и GET (D). Сервер на std.socket хранит словарь в памяти и понимает текстовые команды SET, GET, DEL и QUIT. Клиент отправляет команды с консоли и печатает ответы сервера.

4.4 Сервер вычислений арифметических выражений (Julia). Клиент по сети отправляет выражение с числами, скобками и операциями + − * /, сервер разбирает его своим рекурсивным разборщиком и возвращает результат. Ошибки в выражении и деление на ноль возвращаются клиенту сообщением. Используется модуль Sockets.

## Тема 5. Конвертация данных из одного формата в другой

Папка: `5_convert/`

| № | Задача | Язык | Ветка |
|:-:|:-:|:-:|:-:|
| 1 | CSV в JSON | F# | `5_task_1_fsharp` |
| 2 | JSON в XML | Scala | `5_task_2_scala` |
| 3 | XML в CSV | Groovy | `5_task_3_groovy` |
| 4 | CSV в YAML | Swift | `5_task_4_swift` |

5.1 CSV в JSON (F#). Собственный разборщик CSV понимает кавычки, запятые и переводы строк внутри полей. Первая строка считается заголовком. На выходе массив объектов JSON с экранированием и отступами.

5.2 JSON в XML (Scala). Рекурсивный разборщик JSON строит дерево из объектов, массивов, строк, чисел и литералов true, false, null. Затем дерево печатается как XML с отступами, спецсимволы экранируются.

5.3 XML в CSV (Groovy). Простой XML с однотипными записями разбирается вручную, без готовых XML-парсеров. Собирается полный набор имён полей, таблица выгружается в CSV с экранированием запятых и кавычек, пропущенные поля заполняются пустыми значениями.

5.4 CSV в YAML (Swift). CSV разбирается своим разборщиком, первая строка считается заголовком. Каждая запись выводится как элемент YAML-списка с полями «ключ: значение», строки с особыми символами берутся в кавычки.
